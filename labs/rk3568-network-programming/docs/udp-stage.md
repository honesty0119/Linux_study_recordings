## 实现及原文对应关系

| 原文要求 | 实现 |
| --- | --- |
| SOCK_DGRAM，取消 connect，用 sendto 指定目标 | key_udp 由 key_network.c 使用 TASK2_UDP 宏构建，包含 board/udp_transport.inc；每个 6/8 字节帧对应一次数据报发送 |
| 移除 TCP 断连检测和重连 | UDP 分支没有 connect、TCP 状态检查、重连或应用重传；上位机不监听时仍继续发送 |
| 其他模块保持一致 | 两个构建共用同一 main、adc-keys 采样、10ms 消抖、System V 队列、eventfd 和 task2_core.h 协议编码 |
| 无按键也每 1 秒心跳 | 单调时钟绝对周期；每处理一个按键就重新检查心跳，不累积补发错过的心跳 |
| 上位机绑定端口，直接接收数据报 | Receiver.exe --udp --peer BOARD_IP；ReceiveFrom，不使用 Listen/Accept/Connect；指定板端 IP，允许其源端口在进程重启后变化 |
| 保留解析、日志、2 秒超时 | 复用 Parser、HeartbeatMonitor、AsyncLog；UDP 一包必须恰为一帧，不跨包拼接，不接受多帧合包、尾随字节、坏校验或错误来源 |

无连接不等于本机发送永不失败：若内核报告不可达/缓冲区满，记录 send_failures，丢弃当前数据报并继续调度，不伪报成功、不重放旧按键。socket_sent 只代表本机内核接受，不是接收确认。最终必须同时检查 UDP summary 的 send_failures、队列汇总与上位机计数，不能只看 status=OK。原协议没有应用序号/ACK，无法保证丢包或乱序环境下的可靠传输。

## 运行命令

Windows PowerShell（当前网络地址，运行 60 秒，日志路径必须是新文件）：

```powershell
& '<LOCAL_WORKSPACE>\.local\task2-host\Receiver.exe' 192.0.2.20 8888 60 --udp --peer 192.0.2.10 --log ('<LOCAL_WORKSPACE>\.local\task2-host\udp-' + (Get-Date -Format yyyyMMdd-HHmmss) + '.log')
```

开发板 Linux shell（PuTTY/已授权 SSH，运行 50 秒）：

```sh
/tmp/rk3568-udp.ruoiVt/key_udp 192.0.2.20 8888 /dev/input/event7 50
```

默认仍以 TCP 方式启动 Receiver；只有显式 --udp 才切换。key_network 与 key_udp 是两个可执行文件，不覆盖旧板端 TCP 程序。监听日志中的“连接正常”表示原文定义的心跳状态，不表示 UDP 建立了连接。
