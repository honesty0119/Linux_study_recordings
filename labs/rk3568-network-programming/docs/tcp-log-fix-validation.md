## 已落地的代码

- host/AsyncLog.cs：接收线程非阻塞入队，独立线程按 FIFO 写入并 Flush，有界容量 1024。队列满、写失败、关闭时不能排空均明确返回失败，不丢弃记录后伪报成功。
- host/Receiver.cs：新增 `--log 新的本地文件路径`，程序直接打开文件，避免 PowerShell 标准输出捕获路径引入的干扰。默认控制台输出仍可用；已有文件拒绝覆盖。
- 真实完成指标在最终 `LogSummary` 中：`max_receive_to_log_ms` 包含解析、格式化、排队、实际输出和 Flush。`max_log_enqueue_ms` 仅作接收线程诊断，不能替代完成指标。
- 输出完成指调用返回，不代表屏幕绘制或物理磁盘持久化。直接文件模式可另开终端用 `Get-Content -LiteralPath 日志路径 -Wait` 查看，但查看窗口渲染延迟不在本次指标内。
- 原协议解析、2 秒超时、板端 C 程序及防火墙规则不变。旧版接收器和源码归档在 build/windows/Receiver-sync-baseline.*。

## 构建与检查

Windows PowerShell 执行 host/build.ps1，可同时编译 Receiver.cs、AsyncLog.cs，并运行协议与日志边界检查；默认输出到已放行的本地程序路径。它不改系统网络配置。无须本轮再次交叉编译板端。

当前 Windows 策略拒绝直接运行共享盘上的未签名脚本。已通过把项目构建脚本复制到本地并显式指定源码目录运行；未降低执行策略。复现命令（Windows PowerShell）：

```powershell
$source = '<TASK_DIR>\host'
Copy-Item -LiteralPath (Join-Path $source 'build.ps1') -Destination '<LOCAL_WORKSPACE>\.local\task2-host\build.ps1'
& '<LOCAL_WORKSPACE>\.local\task2-host\build.ps1' -SourceDirectory $source
```

编译警告视为错误，28 项协议自测、15 项异步日志边界检查及真实回环 TCP 集成检查均通过。日志测试故意阻塞输出超过 80ms，确认接收侧入队仍可进行，同时最终记录超过 50ms，避免用异步入队掩盖真实延迟。还覆盖容量溢出、输出失败、有界退出及 FIFO 顺序。既有文件拒绝覆盖且哈希保持不变。

TCP 回归包含拆包/合包、坏校验、重连，以及持续按键不掩盖心跳超时；本轮三次报警约 2015.141、2018.218、2014.853ms。日志位于 logs/async-log/receiver-regression.log。

## 无线侧新增证据

板载 SDIO 驱动为 Realtek RTL8852BS。通用 iw power_save=off；驱动 rtw_lps_mode、rtw_ips_mode、rtw_power_mgnt、rtw_low_power 均为 0。因此未盲目执行“关闭板端省电”的修改。读取结果见 logs/async-log/wireless-state.txt。

重新解析既有 timing3/windows-all.pcapng，按 802.11 帧头和 LLC/SNAP 识别其中被 PktMon 标为 linktype=1 的原生无线帧，以源端口、TCP 序号和负载匹配 23 个心跳。相同 Windows ETW 时钟下，原生无线捕获点→最早 Ethernet 捕获点仅 0.014–0.061ms；两个捕获点都已有相同的约 890.56–1075.59ms 间隔抖动。代码为 tests/analyze_capture_stages.py，逐帧结果 logs/async-log/capture-stages.json。

这进一步缩小范围：该样本的主要抖动在原生无线捕获点之前；不能据此区分板端固件、空口/AP 或 Windows 无线硬件/驱动进入该点之前的等待。原生无线捕获点不是空口时间戳，也不能当作准确单向网络延迟。
